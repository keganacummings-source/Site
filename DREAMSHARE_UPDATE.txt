SLEEPWELL — DreamShare tape posts
=================================

WHY "FAILED TO FETCH" HAPPENED
-------------------------------
Posting a WAV used to send JSON straight from the browser to the public
JSON bin. That host answers the browser's permission check with an error,
so the browser reports "Failed to fetch" and the tape never uploads.
Text posts were fine because they go to your Cloudflare worker.

This build posts small tapes as plain text (no permission check), so library
WAVs and files up to about 6 MB post without that error.

75 MB TAPES — YOU DO NEED A WORKER UPDATE
-----------------------------------------
Yes. Paste WORKER_DREAMSHARE.js again. The public JSON bin caps each piece
at 100 KB and the whole account at about 10 MB, so a 75 MB WAV cannot live
there.

1. dash.cloudflare.com → Workers & Pages → your DreamShare worker
2. Edit code → select all → delete
3. Paste the entire WORKER_DREAMSHARE.js from this package → Deploy
4. Bind storage (do this or tapes over ~6 MB still cannot be saved):

   Best — R2
   Workers → R2 → Create bucket "dreamshare-tapes"
   Worker → Settings → Bindings → R2 bucket
   Variable name: DREAMSHARE_R2

   Or — KV (also works, 4 MB pieces)
   Workers → KV → Create namespace "DREAMSHARE"
   Variable name: DREAMSHARE_KV

5. Open the worker URL. JSON must include:
   "storage": "durable-v4"
   "audioMaxBytes": 78643200
   "audioVault": true

audioVault false means the binding is missing. Text posts still work.
Tapes stay 100 days, then the audio is deleted. The thread text stays.

Do NOT paste WORKER_DREAMSHARE_CLASSIC.js.

ACCOUNTS
--------
Usernames are unique. Log in on the GOODNIGHT homepage. DreamShare uses
that account and has no login of its own.

Post a reel from the floor: library sample, session tape, or Upload WAV
(or drop a .wav on the composer). Hard limit is 75 MB.
